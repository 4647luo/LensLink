# 连镜：反馈与诊断日志

这份说明给用户和后续维护者看：应用出问题时，怎样把足够的信息一次性发回开发者，而不暴露照片和 LUT 原文件。

## 用户怎么发日志

1. 打开「设置 → 关于」。
2. 点「发送诊断日志」：应用会现场生成一个 ZIP，然后拉起系统分享面板，选微信、邮件、蓝牙或其它能发文件的 App 即可。
3. 如果分享面板里没有合适的 App，点「导出诊断日志」，把 ZIP 保存到手机文件里，再手动发送。

ZIP 文件名形如：

```text
lianjing-diagnostics-20261117-2350.zip
```

## ZIP 里有什么

| 目录 / 文件 | 内容 | 是否包含隐私 |
| --- | --- | --- |
| `README.txt` | 本次诊断包的生成说明、版本、目录解释 | 否 |
| `device-info.txt` | 包名、版本、生成时间、时区、语言、厂商、机型、产品、Android 版本、ABI、屏幕参数、日志目录 | 只含设备型号，不含账号 |
| `settings/preset.json` | 当前设置快照，按预设分组导出 | 可能含相机名称、局域网地址、蓝牙地址；不含照片 |
| `logs/` | `DoukLog` 结构化会话日志，单文件 3MB，最多 12 个会话 | 不含照片、视频、LUT 原文件 |
| `xlog/` | xLog 按日期落盘的独立日志，单文件 2MB，启动时清理 7 天前文件 | 不含照片、视频、LUT 原文件 |
| `acra/unapproved/`、`acra/approved/` | ACRA 崩溃报告，含堆栈、版本、机型、系统、logcat、自定义字段 | 不含照片 |

生成时只保留最近 3 个诊断 ZIP；旧包会自动清掉。照片、视频、LUT 立方体文件不会被打进 ZIP。

## 日志分层

- **Timber**：应用代码里的统一门面，`Timber.i/d/w/e` 最终都转给 `DoukLog.write`。
- **DoukLog**：结构化事件日志。固定格式为 `时间 级别/标签: 事件 key=value`，写入 `filesDir/douk-logs/session-*.log`。连接、USB、蓝牙、GPS、图库、编辑、设置等关键路径都用它记录。
- **xLog**：独立文件兜底。`DoukLog.write` 末尾同步写一份到 `filesDir/xlog/YYYY-MM-DD`，即使结构化日志线程被卡住，也能从 xLog 看到最近事件。
- **ACRA**：只收未捕获崩溃。初始化和报告目录由 `DoukApplication` 与 `ReportLocator` 管理，崩溃后下次启动仍能把报告打进诊断包。
- **NetworkLoggingInterceptor**：只记录 HTTP 方法、主机、路径、状态码、耗时、Content-Length；不记录 Authorization、Cookie 和查询参数。

## 开发者拿到 ZIP 后怎么查

1. 先看 `README.txt` 和 `device-info.txt`，确认版本、机型、系统与生成时间。
2. 看 `logs/` 最后一个会话，按时间找 `ERROR`、`WARN`、`USB`、`BLE`、`GPS`、`Gallery`、`Editor` 标签。
3. 崩溃问题先看 `acra/unapproved/` 里的 `.stacktrace`，再用同一时间的 `xlog/` 对照崩溃前最后几条事件。
4. 连接问题看 `settings/preset.json` 里的设备连接组，确认自动连接、默认设备、蓝牙名称与地址是否符合现场。
5. 需要复现时，让用户在同一版本、同一机型上重跑一次，再对比两个 ZIP 的 `logs/` 差异。

## 注意

- 诊断包只用于排错，不要公开发布到公开仓库或社交平台；里面可能含相机名称、局域网地址和蓝牙地址。
- 如果用户不愿意分享设置快照，可以在「设置 → 储存 → 导出预设」里取消「设备连接」组，再单独导出预设；诊断包目前固定带完整设置快照。
- 日志不会记录照片内容，也不会记录相册文件名列表；如果问题与某张照片有关，请用户单独说明拍摄时间、格式和相机内路径。
